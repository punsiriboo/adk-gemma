什么是 Local LLM？

Background — what is a Local LLM?

“本地模型（或 Local LLM）是一种直接在你自己的设备或服务器上运行的 AI 模型，而不是通过互联网使用 AI。” “A local model (Local LLM) is an AI model that runs directly on your own device or server, instead of using AI over the internet.”

☁️ Cloud LLM

提示词和数据通过网络发送到云端 API，由服务商的 GPU 推理后返回结果。Prompt → internet → provider API → response. Pay per request.

App→Internet→Cloud API→Response
vs.

💻 Local LLM

模型权重下载到本机，由 LM Studio 在本地提供 OpenAI-compatible API，数据不离开你的设备。Weights live on your machine; LM Studio exposes an API on localhost.

App / Agent→localhost:1234→Gemma 4

🔒 隐私

数据留在本机。Data never leaves your device.

📴 离线

没有网络也能推理。Works offline.

💸 零调用费

无需按请求付费。No per-request cost.

🛠️ 可控

自由选模型与参数。Full control.

4. 编写第一个 Agent：agent.py

⏱ 10 min

Point the agent at Gemma in LM Studio and give it a Python function tool

step01_basic_agent/agent.py
import datetime
from zoneinfo import ZoneInfo

from google.adk.agents.llm_agent import Agent
from google.adk.models.lite_llm import LiteLlm


def get_current_datetime(timezone: str = "Asia/Shanghai") -> dict:
    """Return the current date and time for a timezone, e.g. Asia/Shanghai or UTC."""
    now = datetime.datetime.now(ZoneInfo(timezone))
    return {"timezone": timezone, "datetime": now.strftime("%Y-%m-%d %H:%M:%S")}


model = LiteLlm(
    model="lm_studio/google/gemma-4-e4b",
    api_base="http://127.0.0.1:1234/v1",
)

root_agent = Agent(
    model=model,
    name="normal_gemma_agent",
    description="A helpful assistant for user questions.",
    instruction=(
        "Answer user questions to the best of your knowledge. "
        "Call get_current_datetime when asked about the date or time."
    ),
    tools=[get_current_datetime],
)

代码解读 · Code walkthrough

  • lm_studio/：LiteLLM 的 LM Studio provider 前缀，后面接模型 id · provider prefix + model id
  • api_base：LM Studio 本地服务地址 · local server URL
  • get_current_datetime：普通 Python 函数就是工具；docstring 和类型注解会告诉模型如何调用 · a plain function is a tool
  • root_agent：ADK 通过这个名字找到入口 Agent · entry point
step01_basic_agent/.env（可选 / optional）
# 也可以不写 api_base，改用环境变量
# Alternative to api_base= in code
LM_STUDIO_API_BASE=http://127.0.0.1:1234/v1
⚠️ 模型 id 必须与 /v1/models 返回的完全一致，否则会得到 404。 · The id must match exactly, or you’ll get a 404.

6. 添加 MCP 工具：Airbnb 搜索

⏱ 10 min

Connect an MCP server with McpToolset — give Gemma a real Airbnb search

step02_mcp_agent/agent.py
from google.adk.agents.llm_agent import Agent
from google.adk.models.lite_llm import LiteLlm
from google.adk.tools.mcp_tool import McpToolset, StdioConnectionParams
from mcp import StdioServerParameters

airbnb_tools = McpToolset(
    connection_params=StdioConnectionParams(
        server_params=StdioServerParameters(
            command="npx",  # requires Node.js
            args=["-y", "@openbnb/mcp-server-airbnb", "--ignore-robots-txt"],
        ),
        timeout=30,  # first npx download can be slow
    ),
)

model = LiteLlm(
    model="lm_studio/google/gemma-4-e4b",
    api_base="http://127.0.0.1:1234/v1",
)

root_agent = Agent(
    model=model,
    name="travel_assistant",
    description="A helpful travel assistant.",
    instruction="Answer user questions. Use the Airbnb tools to find places to stay.",
    tools=[airbnb_tools],
)

7. Workflow：planner → responder

⏱ 5 min

Chain two agents with an ADK 2.x Workflow — share data through output_key

step03_workflow_agent/agent.py
from google.adk.agents import Agent
from google.adk.models.lite_llm import LiteLlm
from google.adk.workflow import START, Workflow

model = LiteLlm(
    model="lm_studio/google/gemma-4-e4b",
    api_base="http://127.0.0.1:1234/v1",
)

planner = Agent(
    model=model,
    name="planner",
    description="Writes a short plan for answering the user.",
    instruction="Write a short numbered plan (3-5 steps) to answer the user. Do not answer yet.",
    output_key="plan",
)

responder = Agent(
    model=model,
    name="responder",
    description="Writes the final answer using the plan.",
    instruction="Use this plan:\n{plan}\n\nWrite the final answer for the user.",
)

root_agent = Workflow(
    name="workflow_gemma_agent",
    description="Planner then responder.",
    edges=[(START, planner, responder)],
)
START→ planner— state["plan"] → responder→ Answer

要点 Key points

  • output_key="plan"：planner 的输出写入 session state · saves output to state
  • {plan}：responder 的 instruction 自动读取 state · injected into the prompt
  • edges=[(START, planner, responder)]：按顺序执行的图 · a sequential graph
Try this prompt / 试试这个提示词
帮我安排一个成都周末两日游
✅ 检查点 Checkpoint — Events 中先看到 planner 的计划，再看到 responder 的最终回答；State 中有 plan。 · Two agents run in order; plan shows in State.

9. Memory：跨会话记住用户

⏱ 5 min

Save each conversation to memory with a callback, recall it later with load_memory

step05_memory_agent/agent.py
from google.adk.agents.llm_agent import Agent
from google.adk.models.lite_llm import LiteLlm
from google.adk.tools.load_memory_tool import load_memory_tool


async def save_to_memory(callback_context):
    """After each turn, save this conversation so other sessions can recall it."""
    await callback_context.add_session_to_memory()


model = LiteLlm(
    model="lm_studio/google/gemma-4-e4b",
    api_base="http://127.0.0.1:1234/v1",
)

root_agent = Agent(
    model=model,
    name="memory_agent",
    description="An assistant that remembers past conversations.",
    instruction=(
        "Answer user questions. "
        "If the user asks about something from a past conversation, "
        "call load_memory with a short keyword query first."
    ),
    tools=[load_memory_tool],
    after_agent_callback=save_to_memory,
)

要点 Key points

  • after_agent_callback：每轮结束后把会话存入 Memory · save after each turn
  • load_memory_tool：模型需要时按关键词检索记忆 · search memory on demand
  • Session = 一次对话；Memory = 跨对话的长期记忆 · session vs. memory
Try it — 两个会话 / two sessions
# Session 1
user  > 我叫 Beat，我最喜欢的川菜是麻婆豆腐。

# ADK Web 右上角 “New Session” 新建会话
# Session 2
user  > 我最喜欢的川菜是什么？
        ⚡ load_memory(query="最喜欢的川菜")
agent > 你最喜欢的是麻婆豆腐！
ℹ️ adk web 默认使用内存型 Memory，重启服务后会清空。 · The default memory service is in-memory — it resets when you restart.
✅ 检查点 Checkpoint — 在新会话中，Agent 通过 load_memory 想起了上一个会话的内容。 · A new session recalls facts from the previous one.
